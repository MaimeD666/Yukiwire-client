# Yukiwire

Клиент для Windows, который подключает приложения к вашему серверу через Xray. Поддерживает VLESS, VMess, Trojan, Shadowsocks и конфигурации JSON Xray.

**Версия: 0.4 preview.** Для подключения нужна своя рабочая ссылка или конфигурация сервера — приложение не выдаёт их само.

## 1. Установка

Нужны **Windows 10/11 x64**, [.NET Framework 4.8](https://dotnet.microsoft.com/download/dotnet-framework/net48) и [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/). Python для готовой сборки не нужен.

Откройте [Releases](https://github.com/MaimeD666/Yukiwire-client/releases) и выберите один вариант:

| Файл | Что делать |
|---|---|
| `Yukiwire-…-win-x64-setup.exe` | Запустите установщик. Yukiwire появится в меню «Пуск», а удалить его можно будет через настройки Windows. |
| `Yukiwire-…-win-x64.zip` | Распакуйте архив целиком в отдельную папку и запустите `Yukiwire.exe`. |

Если релиза ещё нет, готовые файлы можно взять в [Actions](https://github.com/MaimeD666/Yukiwire-client/actions): откройте успешный запуск **Checks**, скачайте артефакт **Yukiwire-0.4-preview-win-x64** и распакуйте его. Для скачивания артефактов нужен вход в GitHub. Ниже также описана сборка из исходников.

Установщик работает для текущего пользователя и при необходимости загружает WebView2 через официальный компонент Microsoft. Для portable-варианта WebView2 нужно установить отдельно, если его ещё нет. Программа и установщик пока не имеют цифровой подписи.

## 2. Первое подключение

1. Откройте Yukiwire и перейдите в «Профили».
2. Добавьте ссылку подключения или JSON Xray и сохраните профиль.
3. На главном экране выберите профиль, режим и маршрут.
4. Нажмите «Подключиться». Чтобы закончить сеанс, нажмите «Отключиться».

JSON от Clash и sing-box не поддерживается. Ссылки и конфигурации с неподдерживаемыми параметрами отклоняются с объяснением.

### Какой режим выбрать

| Режим | Когда использовать |
|---|---|
| **Локальный прокси** | Для отдельного браузера или программы с ручной настройкой прокси. Подходит для работы рядом с другим VPN. После подключения нажмите «Открыть браузер». |
| **Системный прокси** | Для браузеров и приложений, которые используют настройки прокси Windows. Не захватывает весь трафик компьютера. |
| **TUN** | Для захвата IPv4, IPv6 и UDP на уровне сетевого интерфейса. При подключении Windows запросит права администратора для сетевого помощника. |

Запускайте само приложение обычным способом. Для системного прокси и TUN сначала завершите другой VPN. Плашка конфликта обновляется примерно каждые 5 секунд; она останется, если после закрытия другого клиента сохранились его прокси или маршруты.

В локальном режиме кнопка «Открыть браузер» запускает отдельный профиль Chrome или Edge через Yukiwire. Для ручной настройки других программ используйте HTTP `127.0.0.1:11809` или SOCKS5 `127.0.0.1:11808`.

### Какой маршрут выбрать

- **РФ напрямую** — российские домены и локальная сеть напрямую, остальное через сервер. Российские IP включаются отдельно.
- **Всё через VPN** — внешний трафик через сервер, локальная сеть напрямую.
- **Только выбранное** — через сервер идут только заданные правила и списки блокировок.
- **Правила из JSON** — маршрутизацией управляет импортированная конфигурация Xray.

В разделе «Маршруты» можно добавить свои исключения и проверить предполагаемый маршрут адреса. Списки обновляются при отключённом соединении. Если работает другой VPN, «напрямую» означает текущее подключение Windows, которое тоже может проходить через него.

## 3. Обновление и данные

Для обновления установленной версии завершите Yukiwire через «Выход» в трее и запустите новый установщик. Профили и настройки сохранятся. Удаление через Windows также оставляет личные данные для возможной переустановки.

Профили защищены Windows DPAPI текущего пользователя. У готовой сборки данные находятся в папке `state` рядом с приложением; при запуске из исходников — в `runtime/state`. Свежая установка не переносит профили из другой папки автоматически. Portable-архив сам по себе не делает зашифрованные профили переносимыми между пользователями Windows.

Если восстановление сети не завершилось, откройте настройки Yukiwire и выполните восстановление. Установщик блокирует обновление и удаление, пока остаётся такой журнал. Не удаляйте его вручную вместо восстановления.

Версия предварительная. Автоматические проверки покрывают разбор конфигураций, маршруты, остановку процессов и восстановление собственных изменений. Полные сценарии TUN, сна, смены сети и выключения Windows требуют отдельных испытаний на реальной системе.

## 4. Запуск из исходников

Для разработки нужны **Git**, **Python 3.11+ x64**, Windows и компоненты из раздела установки. Node.js и npm не нужны. Команды ниже выполняются в PowerShell.

Если хотите сделать свою версию, сначала нажмите **Fork** на GitHub и замените адрес в `git clone` адресом своего форка.

```powershell
git clone https://github.com/MaimeD666/Yukiwire-client.git
cd Yukiwire-client
py -3 -m venv .venv
.\.venv\Scripts\python.exe scripts/download_core.py
.\.venv\Scripts\python.exe scripts/download_wintun.py
.\.venv\Scripts\python.exe -m yukiwire
```

Первый запуск соберёт Windows-окно и скачает закреплённый WebView2 SDK. Сетевое ядро, зависимости и локальные данные сохраняются в `runtime/`. Компилятор C# используется из .NET Framework; Visual Studio для этой сборки не нужна.

После изменений закройте приложение и повторите последнюю команду. Активация виртуального окружения не требуется: в командах явно указан его Python.

### Где что менять

| Путь | Назначение |
|---|---|
| `ui/index.html`, `ui/styles.css`, `ui/app.js` | Экраны, внешний вид и поведение интерфейса |
| `native/WebShell.cs` | Окно Windows, WebView2, трей и обмен с сервисом |
| `native/NetworkWorker.cs` | Запуск сетевого помощника |
| `native/IconBuilder.cs`, `ui/assets/icon.svg` | Иконка приложения; ICO генерируется при сборке |
| `yukiwire/` | Профили, конфигурации Xray, маршруты, сеть и восстановление |
| `tests/` | Автоматические проверки |
| `scripts/` | Загрузка зависимостей, сборка и интеграционные проверки |
| `packaging/windows/` | Сценарий установщика |

Интерфейс передаёт команды отдельному сервису; он управляет Xray. Только помощник TUN запрашивает повышение прав. При изменениях сетевой части сохраняйте восстановление собственных настроек, проверку владельца процессов и изоляцию от других VPN.

### Проверки

Перед проверками завершите запущенный Yukiwire, чтобы освободить его локальные порты.

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe scripts/verify_ui.py
```

Тесты интерфейса используют установленный Microsoft Edge. Интеграционные тесты запускают собственные процессы; тест Планировщика создаёт и удаляет отдельную задачу текущего пользователя. Отчёты и снимки тестов остаются в `runtime/`.

Для исправления или новой функции создайте ветку, внесите изменения и откройте pull request. Опишите, что изменилось и как это проверялось. Конфигурации серверов и личные профили в коммиты не добавляйте; в примерах используйте вымышленные данные.

## 5. Сборка ZIP и установщика

Из подготовленного окружения выполните:

```powershell
.\.venv\Scripts\python.exe scripts/build_portable.py
.\.venv\Scripts\python.exe scripts/build_installer.py
```

Portable-сборка автоматически получает закреплённый embedded Python. Для установщика загружаются Inno Setup в portable-режиме и официальный WebView2 bootstrapper; проверяются контрольные суммы и подписи издателей. Системная установка Inno Setup не нужна.

Результат в `dist/`:

- `Yukiwire-0.4-preview-win-x64.zip`;
- `Yukiwire-0.4-preview-win-x64-setup.exe`;
- `SHA256SUMS.txt`.

Проверка готовых файлов:

```powershell
.\.venv\Scripts\python.exe scripts/verify_portable.py dist/Yukiwire-0.4-preview-win-x64.zip --native
.\.venv\Scripts\python.exe scripts/verify_installer.py
```

Проверка установщика ставит, обновляет и удаляет отдельную тестовую копию внутри `build/`; для неё WebView2 уже должен быть установлен.

GitHub Actions выполняет проверки и сохраняет эти три файла как артефакт. Публичные релизы автоматически не создаются. Готовые сборки предназначены для **Releases**, а в репозитории хранятся исходники, тесты и сценарии сборки.
