## 🔴 Критично

### 1. Повышение привилегий (LPE) через установку в папку пользователя

**Где:** `packaging/windows/Yukiwire.iss`, `native/WebShell.cs` (`StartNetworkWorker`), `native/NetworkWorker.cs`, `yukiwire/startup.py`, `scripts/startup-recovery.ps1`, `yukiwire/network.py` (`_recover_journal`).

**Суть.** Установщик ставит программу в `%LOCALAPPDATA%\Programs\Yukiwire` (`PrivilegesRequired=lowest`). Эта папка доступна на запись любому процессу пользователя. В режиме TUN оттуда с правами администратора запускаются:

- `python\python.exe`;
- `scripts\worker.py` и весь пакет `yukiwire\*.py`;
- `xray.exe` и `wintun.dll`;
- `recover-tun.ps1` с `-ExecutionPolicy Bypass`.

Вредонос без прав админа подменяет любой из этих файлов и получает админа, когда пользователь подтверждает UAC «Yukiwire».

**Хуже.** `startup.py` регистрирует задачу планировщика с `RunLevel Highest` и триггером AtLogOn. Она запускает Python из той же папки при входе в систему **без запроса UAC**. Это готовый тихий обход UAC с закреплением в системе. Задача существует всю TUN-сессию, а после краша остаётся до восстановления.

**Дополнительно:**
- `NetworkWorker` берёт путь к Python из `argv[4]`, если встроенного интерпретатора нет;
- в dev-режиме путь берётся из переменной `YUKIWIRE_PYTHON`.

**Как исправить:**
- per-machine установка в Program Files (установщик с правами админа);
- повышенные права только у отдельного минимального бинаря или службы, которая умеет только поднимать и убирать адаптер и маршруты;
- задача восстановления без Highest, либо она запускает только подписанный exe из защищённой папки;
- не принимать путь к интерпретатору из аргументов и переменных окружения в elevated-процессе.

### 2. Открытые локальные прокси без аутентификации

**Где:** `yukiwire/config.py` (`build_config`), `yukiwire/health.py` (`diagnostic_config`), `yukiwire/telemetry.py` (`enable_metrics`).

| Порт | Что | Проблема |
|------|-----|----------|
| 11808 | SOCKS | `auth: noauth` |
| 11809 | HTTP | без аутентификации |
| 11812 | HTTP (проверки) | весь трафик идёт в proxy **в обход правил**, включая RU-домены |
| 11811 | gRPC API (StatsService) | доступен любому локальному процессу |

**Суть.** Любое приложение на ПК может найти прокси по известному порту, сходить через него на сервис определения IP и узнать адрес твоего сервера. Именно так приложения детектят VPN и сливают серверы под блокировку. Все порты слушают и в режиме TUN, где они не нужны.

**Как исправить:**
- случайные порты при каждом запуске;
- аутентификация на SOCKS;
- порт 11812 поднимать только на время проверки или ограничить его правилами;
- API на случайном порту;
- в чистом TUN (без `tun_system_proxy`) локальные inbound не поднимать.

## 🟠 Высокая важность

### 3. Нет kill switch

**Где:** `yukiwire/backend.py` (`_restart`, `Session.stop`), `yukiwire/network.py` (`add_tun`).

- Если ядро падает в TUN, маршруты `0.0.0.0/1`, `128.0.0.0/1` исчезают, и трафик идёт напрямую, пока работает переподключение (бэкофф до 30 с).
- В режиме системного прокси восстанавливается исходный прокси, и трафик тоже идёт напрямую.
- `autoSystemWfpBlockLeak` защищает только DNS и некорректную настройку TUN.

**Как исправить:** опциональный WFP-фильтр, который блокирует весь трафик кроме адреса сервера на время переподключения.

### 4. Бинарники не подписаны

**Где:** `scripts/build_native.py`, `scripts/build_installer.py`, `.github/workflows/release.yml`.

- Нет Authenticode-подписи, поэтому будут ругаться SmartScreen и антивирусы.
- Связка «скрытые окна + schtasks + `powershell -ExecutionPolicy Bypass` + встроенный Python» выглядит для эвристик как типичная малварь.
- Подлинность сборки можно проверить только по `SHA256SUMS.txt` с того же GitHub.

**Как исправить:** подписывать exe и установщик (хотя бы через SignPath для open source или Azure Trusted Signing).

### 5. Хэш ядра Xray не запинен

**Где:** `scripts/download_core.py`.

Архив Xray сверяется с файлом `.dgst`, скачанным из того же релиза. Если релиз подменён, подменён и `.dgst`, так что проверка фактически ничего не даёт. Wintun, Python и WebView2 при этом запинены, а самый важный компонент нет.

**Как исправить:** константа `SHA256` в скрипте, как в `download_wintun.py`.

### 6. Нет автообновления

Нет даже проверки новой версии. Если в Xray найдут уязвимость, у пользователей останется старое ядро навсегда.

**Как исправить:** хотя бы проверка последнего релиза через GitHub API и уведомление в UI.

### 7. Весь бэкенд работает с правами админа в TUN

**Где:** `native/NetworkWorker.cs`, `yukiwire/backend.py`.

В TUN-режиме под повышенными правами работает весь `backend.py`: парсинг ссылок, JSON-профилей, загрузка списков с GitHub, обработка правил. Это нарушение принципа наименьших привилегий и усиливает пункт 1: любая ошибка в парсере становится ошибкой с правами админа.

**Как исправить:** вынести в elevated-хелпер только операции с адаптером и маршрутами, всё остальное оставить в обычном процессе.

## 🟡 Средняя важность

### 8. Слишком строгий парсер ссылок

**Где:** `yukiwire/config.py`.

Ссылка отклоняется целиком из-за любого незнакомого параметра. Проверено на реальных строках:

| Ссылка | Результат |
|--------|-----------|
| VLESS с `headerType=none` (типично для панелей) | ❌ отказ |
| VLESS с `pqv` (новый Reality) | ❌ отказ |
| Trojan с `allowInsecure` | ❌ отказ |
| Trojan с `peer` | ❌ отказ |
| VLESS с транспортом `httpupgrade` | ❌ отказ |
| `hy2://` | ❌ отказ |
| Reality без `pbk` | ✅ принимается, падает уже в ядре с невнятной ошибкой |

Нет транспортов KCP и H2, протоколов WireGuard и Hysteria, хотя Xray их поддерживает (`wireguard` отсутствует в `safe_outbounds`).

**Как исправить:** игнорировать неизвестные параметры с предупреждением, валидировать обязательные (`pbk` для Reality), добавить `httpupgrade`.

### 9. Нет подписок, QR, пинга, выбора сервера

Для большинства пользователей VPN-сервисов подписка — основной сценарий. Сейчас каждый сервер нужно добавлять вручную, нельзя сравнить задержку и выбрать лучший.

### 10. Ложные конфликты с другими клиентами

**Где:** `yukiwire/network.py` (`conflicts`).

- Клиент отказывается запускаться, если просто запущен процесс `nekoray.exe`, `v2rayn.exe`, `clash.exe` и т. п., даже если они в трее без подключения.
- Отказ, если включён любой системный прокси или PAC.
- Список имён неполный: например, Throne, Happ, Amnezia и Outline в нём нет.

Проверка маршрутов в `windows_snapshot.foreign_capture_present` сделана правильно. Список имён процессов лишний и даёт ложные срабатывания.

**Как исправить:** опираться только на реальные маршруты и адаптеры, а не на имена процессов.

### 11. DNS в TUN жёстко зашит

**Где:** `yukiwire/network.py` (`add_tun`), `yukiwire/routing.py`.

Всегда DoH `1.1.1.1` через VPN, в том числе для российских доменов, которые идут напрямую. Российские CDN из-за этого отдают узлы под страну выхода, и всё грузится медленнее. Поменять DNS нельзя.

**Как исправить:** раздельный DNS — для direct-доменов системный или российский резолвер, для proxy — DoH через VPN; выбор DNS в настройках.

### 12. Проблемы с обновлением списков маршрутов

**Где:** `yukiwire/geodata.py`, `yukiwire/routing.py`.

- Списки обновляются только с GitHub (api и raw), а он в РФ бывает замедлен.
- Лимит GitHub API без токена — 60 запросов в час.
- Обновить можно только при выключенном VPN.
- Во встроенных geo-файлах Xray нет `ru-blocked`, поэтому до первого обновления режимы «Все, кроме РФ» и «По списку» работают урезанно.

**Как исправить:** разрешить обновление через активный VPN, добавить зеркало, поставлять готовые списки в сборке.

### 13. Тестовые режимы в релизном бинаре

**Где:** `native/WebShell.cs` (`Main`, `Integration`, `Smoke`).

В production попадают `--integration*`, `--smoke`, чтение произвольного файла из argv и `Page.crash` через DevTools Protocol.

**Как исправить:** вынести под `#if DEBUG` или в отдельную тестовую сборку.

### 14. Гонки между потоками

**Где:** `yukiwire/backend.py`.

Флаги `restarting`, `healthy` и `failed_checks` меняются из нескольких потоков (`_monitor`, `_worker`, потоки проверок) без блокировки. Возможны двойные перезапуски или пропущенные сбои.

**Как исправить:** общий lock на состояние сервиса или перевести всю логику состояния в один поток-обработчик команд.

### 15. Постоянный опрос системы

**Где:** `yukiwire/telemetry.py`, `yukiwire/backend.py` (`_monitor`, `_environment_monitor`).

- Каждые 2 с запускается новый процесс `xray api statsquery`.
- Каждые 5 с делается снапшот процессов и маршрутов, причём дважды: в `_monitor` и в `_environment_monitor`.

Это нагрузка на CPU и батарею плюс сканы антивируса на каждый запуск процесса.

**Как исправить:** ходить в gRPC API напрямую, объединить мониторы.

## 🟢 Низкая важность

### 16. Лишняя сетевая активность при подключении

**Где:** `yukiwire/health.py`, `yukiwire/browser.py`.

- При каждом подключении клиент стучится на 5 сайтов (`example.com`, `github.com`, `www.youtube.com`, `chatgpt.com`, `auth.openai.com`), в cloudflare trace и на chatgpt. Это лишний трафик и узнаваемый паттерн.
- Кнопка «Открыть браузер» всегда открывает `chatgpt.com`.

**Как исправить:** проверять сайты только по кнопке, стартовую страницу браузера сделать настраиваемой.

### 17. Ограничения DPAPI

**Где:** `yukiwire/storage.py`, `yukiwire/paths.py`.

- Portable-версия хранит профили рядом с exe. На другом ПК или под другим пользователем они не расшифруются, а пользователь получит общую ошибку.
- Энтропия DPAPI — константа из открытого кода, так что любой процесс этого же пользователя расшифрует профили. Это защита только от копирования файла, не от малвари.

**Как исправить:** экспорт и импорт профилей, понятное сообщение при невозможности расшифровать.

### 18. Требования к платформе

- Только Windows 10/11 x64.
- Нужен .NET Framework 4.8.
- WebView2 установщик докачивает из интернета, офлайн-установка невозможна.

## 🛠 Для разработчика

### 19. Избыточная архитектура

- Для одного клиента используются Python, C# WPF, WebView2, PowerShell, планировщик задач, named pipes и Job objects.
- `backend.py` — god-object на 769 строк, `_command` — цепочка if/elif примерно на 250 строк.

**Как исправить:** разбить `_command` на обработчики по словарю действий, вынести сессию, профили и правила в отдельные сервисы.

### 20. Хаки и хардкод

- Trojan и VMess собираются через фиктивную VLESS-ссылку с поддельным UUID (`other_link` в `config.py`). Это хрупко.
- Порты захардкожены примерно в 14 местах.
- Версия `'0.4'` размазана по коду, User-Agent и workflow.
- Версия Python расходится: README говорит 3.11+, CI использует 3.11, `download_python.py` качает 3.14.8.

**Как исправить:** один модуль с константами (порты, версия), прямое построение outbound для каждого протокола.

### 21. Ручной CI для релизов

**Где:** `.github/workflows/release.yml`, `.github/workflows/check.yml`.

- В `release.yml` вручную захардкожены `BUILD_RUN_ID` и коммит, на каждый релиз их нужно править руками.
- Actions пинятся по тегу (`@v4`), а не по SHA коммита.

**Как исправить:** релиз по тегу, артефакт из того же запуска, пины actions по SHA.

### 22. Нет пользовательских логов

stderr ядра глотается, диагностика урезана до категорий. Приватность хорошая, но реальные баги дебажить почти нечем.

**Как исправить:** opt-in подробный лог с маскировкой адресов и UUID.

## ✅ Что сделано хорошо

- Конфиг передаётся в Xray через stdin и не попадает на диск.
- Job object с `KILL_ON_JOB_CLOSE`: ядро умирает вместе с владельцем.
- Журнал восстановления прокси с проверкой PID и времени старта процесса.
- `allowInsecure=false` по умолчанию.
- В UI строгий CSP и нет `innerHTML`.
- WebView заблокирован: навигация только на свой origin, нет DevTools, разрешения запрещены.
- Списки маршрутов проверяются по Git blob.
- Wintun, Python и WebView2 запинены по SHA256.
- `._pth` во встроенном Python отключает `PYTHONPATH`.
- 156 тестов.

## Порядок исправления

1. Убрать повышение прав из папки пользователя: per-machine установка и отдельный минимальный elevated-хелпер (пункты 1, 7).
2. Случайные порты и аутентификация на локальных inbound, убрать постоянный 11812 (пункт 2).
3. Kill switch через WFP-блок на время переподключения (пункт 3).
4. Запинить хэш Xray и подписать сборки (пункты 4, 5).
5. Смягчить парсер ссылок, добавить подписки (пункты 8, 9).
6. Убрать тестовые режимы из релиза и починить гонки (пункты 13, 14).
